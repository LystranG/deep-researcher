Observation 回流、暂停恢复与预算停止

这个 demo 只回答一个问题：Plan-and-Solve 外层和单 Research Task 内有界 ReAct，是否能用少量可观察状态表达恢复、幂等、租约 fencing、预算和 Verifier 屏障？每次操作后都会显示完整业务事实

原型边界：所有事实都在内存中；这里模拟的是业务数据库已提交的 Observation、Outcome、Run Event 和 checkpoint 引用，不代表生产表结构或 LangGraph 节点

引导场景

观察：Tool Observation 提交后才回流下一次 Model Turn；Task Outcome 产生后还要经过调度屏障才允许 Verifier

1. 认领并推进 Model Turn 1模型只提出一个 Tool Call
2. 执行同步 Tool副作用计数只增加一次，Observation 持久化
3. 用 Observation 推进 Model Turn 2Controller 形成不可变 Task Outcome
4. 形成调度屏障并运行 Verifier只提交一个 complete/replan/partial/failed

观察：异步 Tool 进入 waiting；完成后只用稳定 task_id 恢复，不携带临时 resume payload

1. 推进到异步 Tool结果应为 waiting
2. 让异步 Worker 完成只写入业务 Observation
3. 用同一 task_id 恢复结果应为 runnable 或 terminal

观察：Tool 成功后、Task 恢复前崩溃；重放 checkpoint 不应再次执行已成功副作用

1. 执行同步 Tool 并提交 Observation记录副作用计数
2. 在恢复前模拟崩溃丢弃控制流快照，但保留业务事实
3. 重放并恢复 Task副作用计数必须保持 1

观察：Worker 接管后 lease_epoch 递增；旧 Claim 提交会被拒绝，不能改写业务事实

1. Worker A 认领保存 epoch 1 的 TaskClaim
2. Worker B 接管epoch 变为 2
3. Worker A 用旧 Claim 提交结果应为 lease_lost

观察：停止原因来自可解释的业务预算，而不是 Graph recursion limit 或模型自报完成

1. 连续两次成功推进但无 Evidence GainTask 应形成 no_evidence_gain 停止事实
2. 消耗到 Model Turn 上限Task 应形成 turn_budget_exhausted 停止事实
3. 观察 Run 总预算token/cost/deadline 不能因恢复而扩大

观察：Verifier 只有在当前计划阶段所有 Task Outcome 已持久化后运行一次；结果互斥且幂等

1. 选择 Verifier 输入覆盖、缺口、冲突和可发布 Claim 会影响路由
2. 形成调度屏障屏障前执行 Verifier 会被拒绝
3. 重复执行 Verifier返回同一个 decision，不追加第二个裁决

观察：checkpoint 只保存稳定引用和游标；丢失或重放不会改写 Observation、Outcome 或副作用

1. 提交业务事实并保存 checkpoint页面展示两个来源的职责
2. 模拟 checkpoint 丢失业务事实仍然存在
3. 从稳定 ID 重放事件数和副作用数不增加
