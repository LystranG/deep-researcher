一次性逻辑原型 · 原型验证 Research File Space 与 Sandbox 文件往返

一个文件从来源进入 Sandbox，再成为可恢复产物

此原型只回答状态模型问题：模型面对的是否仍是少量结构化 Tool，而 File Space Module 能否在内部守住 Revision、Capability、CAS、幂等重试、输出回收、Artifact provenance 与 tombstone

原型边界：所有状态只存在浏览器内存，不验证 PostgreSQL、对象存储、容器隔离或真实 Worker。它验证业务语义和恢复路径，不修改生产实现

目标：确认 Sandbox 排队时 pin 输入，暂态失败重试不重复逻辑 Tool Call

3Worker 接管并成功输出先进入 staging，不直接成为 Artifact
4回收输出staging 字节摄取为 Blob 和 work Revision 后才发布 Observation

目标：确认 publish 产生 Artifact 版本并保留完整 provenance

1发布第一版图表work Revision 复用 Blob，形成 Artifact Revision

3软删除 Artifact从路径和普通检索隐藏，不破坏历史 Observation

目标：确认重放只读取业务事实，不再次执行 Sandbox 副作用

1模拟 Worker / Graph 崩溃Checkpoint 只保留稳定 ID 和恢复游标
